# Lytai Studio 产品站设计文档

## 1. 项目结论

Lytai Studio 应被定义为主产品。

Seedance 2.0 不再作为站点主角，而是作为 Lytai Studio 内的一个核心能力模块存在，承担以下角色：

- 视频生成与多模态创作能力来源
- Cookbook 文档中的重点能力章节
- 首页与案例区中的能力说明标签

站点目标不再是“介绍 Seedance 2.0 是什么”，而是“让用户理解并开始使用 Lytai Studio”。

## 2. 产品定位

### 2.1 产品定义

Lytai Studio 是一个面向创作者的多模态内容生成工作台，帮助用户通过提示词、图像、视频和音频参考素材完成视频与图像创作。

### 2.2 核心价值

- 用自然语言快速发起创作
- 用参考素材提高可控性
- 用能力模块降低创作试错成本
- 用案例和文档缩短上手路径

### 2.3 品牌关系

- 主品牌：Lytai Studio
- 能力模块：Seedance 2.0
- 文档命名：Cookbook / Guides / Capabilities

不再使用“Seedance 2.0 用户手册”作为整个站点的上位命名。

## 3. 当前问题

### 3.1 品牌叙事分裂

当前首页在讲 Lytai Studio，文档主体在讲 Seedance 2.0，用户会产生以下混淆：

- 这是谁的产品站
- Seedance 2.0 与 Lytai Studio 是什么关系
- 首页和文档是不是两个不同站点

### 3.2 首页首屏不够强

当前首页已经有工作台结构，但首屏缺少一个真实、强势、可记忆的视觉锚点。品牌名、说明文案、输入框的组合更像工具入口，不像旗舰产品站首页。

### 3.3 灵感区缺少产品真实性

当前 Discover 流采用占位图片，不承载真实案例或能力展示，削弱了产品可信度，也无法支撑“高端创作产品”的感知。

### 3.4 文档与产品首页缺少统一叙事

当前文档布局是标准技术文档骨架，结构可用，但命名、标题、正文语气仍然围绕 Seedance 2.0 展开，未体现其作为 Lytai Studio 能力模块的从属关系。

## 4. 设计目标

本次改版不追求“更炫”，而追求以下四点：

- 让用户在第一屏知道产品是谁
- 让用户在第一屏知道能做什么
- 让用户能在最短路径内开始创作
- 让文档成为产品转化的一部分，而不是独立内容岛

## 4.1 当前实现状态

截至当前版本，以下内容已经落地：

- 首页已切换为产品站叙事，突出 `Lytai Studio` 主品牌
- 首页 Hero 已使用真实案例媒体，不再使用纯标题区
- 首页案例区已替换占位图流，改为真实 image / video 案例卡片
- 已新增 `Create` 页面，并接入中英文路由
- `Create` 已恢复为聊天式生成工作台：提示词保留在主 feed 中，生成结果以结果卡片形式回写
- `Create` 会把最近生成的 image / video 结果写入本地历史
- `Account` 已接入本地生成历史，可切换查看 image / video 结果

以下内容仍未完成：

- Cookbook 全量命名与导航体系仍未完全从“Seedance 2.0 用户手册”转成产品站语境
- Capabilities 一级页面尚未建立
- 创作页尚未接入真实后端生成链路，当前结果历史使用本地记录机制承接交互

## 5. 设计总纲

### 5.1 Visual Thesis

黑色基底、冷青强调、电影感媒体、极简界面，让产品气质从“文档站”转向“高级创作系统”。

### 5.2 Content Plan

首页内容顺序应固定为：

1. Hero
2. Capability Proof
3. Workflow
4. Cookbook Entry
5. Final CTA

### 5.3 Interaction Thesis

交互不应靠大量小组件堆砌，而应用少量明确动效建立高级感：

- 首屏媒体与文字分层入场
- 案例区域滚动显现
- Hover 时强化可点击媒体与主操作

## 6. 信息架构

### 6.1 一级结构

- Home
- Create
- Capabilities
- Cookbook
- Account

### 6.2 一级结构说明

`Home`
产品入口页，负责品牌表达、能力概览、案例证明和创作入口。

`Create`
实际创作工作台，重点是 prompt、参考素材、参数控制与生成结果。

`Capabilities`
能力说明页，介绍如视频生成、多模态参考、镜头运动、音频驱动、编辑等模块。

`Cookbook`
偏教程和范例的知识区，用于降低学习门槛。

`Account`
用户资料、额度、会员等级、历史状态等。

### 6.3 Seedance 2.0 的位置

Seedance 2.0 不再占据一级导航主品牌位。

推荐改为以下任一方式：

- `Capabilities > Seedance 2.0 Video Engine`
- `Cookbook > Seedance 2.0`
- `Powered by Seedance 2.0` 形式出现在能力说明区

## 7. 首页设计

### 7.1 首页职责

首页只做五件事：

- 建立品牌认知
- 展示结果质量
- 解释创作方式
- 提供进入创作的入口
- 把用户导向案例与文档

### 7.2 Hero

Hero 必须从“标题 + 输入框”升级为“品牌 + 真实作品 + 创作入口”。

推荐结构：

- 左侧或下方窄文本列
- 一条明确 headline
- 一句功能说明
- 一个主 CTA：Start Creating
- 一个次 CTA：Explore Cookbook
- 一个真实视频作品作为主视觉

推荐 headline 示例：

`Direct your next scene with prompts, references, and motion.`

推荐辅助说明：

`Lytai Studio turns text, images, video, and audio into controllable visual creation workflows.`

Hero 中必须出现真实视频或高质量生成片段，不能再用纯空白标题区承担首屏视觉。

### 7.3 Capability Proof

该区块回答“为什么值得用”。

只保留 3 个核心能力，不做大而全罗列：

- Multi-modal Reference
- Motion and Camera Control
- Video Editing and Extension

每项能力应包含：

- 能力名
- 一句话解释
- 一个真实案例缩略媒体

### 7.4 Workflow

该区块回答“怎么用”。

推荐 3 步：

1. Write the prompt
2. Add references
3. Generate and refine

不要做成营销卡片，可采用横向步骤条、分栏说明或小型流程带。

### 7.5 Cookbook Entry

Cookbook 区块不再以“Seedance 2.0 用户手册”为标题出现。

推荐命名：

- Learn the system
- Cookbook for controlled creation
- Guides for prompts, motion, and editing

该区块职责是引导，而不是再次长篇解释。

### 7.6 Final CTA

页面底部只保留一个动作主线：

- Start Creating

次级入口可保留：

- Browse Cookbook

## 8. 创作页设计

### 8.1 页面性质

创作页是产品工作台，不是营销页面。

因此应坚持以下原则：

- 以输入与结果为中心
- 减少装饰性大标题
- 减少无意义内容块
- 通过布局而非卡片堆叠组织界面

### 8.2 页面布局建议

- 左侧：导航与全局状态
- 中央：Prompt + 素材上传 + 参数
- 右侧或下方：结果区 / 历史结果 / 预览

当前实现状态：

- 已采用左侧导航 + 中央聊天式生成 feed + 右侧摘要栏的结构
- Prompt 输入区固定在主 feed 底部，保持“输入一次，结果回写一次”的节奏
- 右侧展示当前草稿摘要和最近结果，避免把主工作区切成仪表盘式卡片墙

### 8.3 输入区原则

- Prompt 输入框是页面主角
- 参考素材上传应更明确显示其用途
- 参数选项应减少视觉噪声
- 生成按钮必须始终显眼

当前实现状态：

- 已保留原有聊天式输入框作为主操作区
- 已保留模式、比例、时长等轻量控制项
- 下一步应继续把“参考内容”入口从装饰态提升为真实上传入口

### 8.4 当前可保留元素

- 黑色基础界面
- 左侧极简导航壳
- Prompt 输入核心交互
- 账号与语言切换的轻量弹层

### 8.5 需要调整的地方

- 提升主按钮权重
- 把“参考内容”从装饰按钮改成明确上传入口
- 减少次要小控件视觉竞争
- 让结果区域更像作品展示，而不是普通播放器容器

已完成部分：

- 结果区已经从纯摘要改为聊天流中的结果卡片
- 结果卡片支持 image / video 两种结果形式
- 最新结果会同步进 `Account` 的历史结果区域

## 9. 文档设计

### 9.1 文档定位

Cookbook 是产品转化系统的一部分，不是独立知识站。

当前实现状态：

- 首页与 Create 的品牌叙事已完成收口
- 文档区仍保留现有结构，但还需要继续做命名和文案迁移

## 9.5 Account 结果历史

`Account` 页不应只展示用户身份信息，还要承担“查看最近生成结果”的职责。

推荐结构：

- Identity / Session 信息保留在上方与右侧
- 主内容区保留 image / video 切换
- 切换后展示最近生成结果历史，而不是静态占位库

当前实现状态：

- 已通过本地生成历史接入 image / video 结果展示
- `Create` 产生的新结果会同步到 `Account`
- 当前历史来源是本地浏览器存储，后续可替换为真实服务端记录

### 9.2 文档命名

当前类似“Seedance 2.0 使用手册”的命名应调整为：

- Cookbook
- Guides
- Creative Control Guides

Seedance 2.0 可作为某个子章节名，而不是整个文档体系名。

### 9.3 文档结构建议

- Getting Started
- Prompting
- References
- Camera and Motion
- Editing and Extension
- Audio and Rhythm
- Seedance 2.0 Engine

### 9.4 文档风格原则

- 标题更工具化
- 段落更短
- 案例先于长文
- 参数、限制、注意事项模块化
- 减少宣传腔，增加操作指导语气

## 10. 视觉系统

### 10.1 色彩

保留当前深色方向，但明确角色分工：

- Background: 纯黑到深灰
- Surface: 稍亮一层的黑灰
- Text Primary: 高亮灰白
- Text Secondary: 低对比灰
- Accent: 冷青或青蓝

强调色只用于：

- CTA
- Active 状态
- 关键标签

不应用于大面积装饰。

### 10.2 字体

建议两套字体以内：

- 英文标题：更有识别度的展示字体
- 正文与 UI：清晰、克制的无衬线字体

如果暂时不引入新字体，至少应在字号、字重、字距上建立更明显层级，不让标题和正文都落入同一套普通 UI 文本语气。

### 10.3 圆角与边框

当前圆角体系基本可保留，但要控制使用层级：

- 大容器：`rounded-2xl`
- 小控件：`rounded-lg` 或更小
- 边框：只用于分层，不用于装饰

### 10.4 图标

图标仅辅助扫描，不应成为视觉主角。

首页尤其应降低图标密度，把视觉资源让给真实媒体案例。

## 11. 动效系统

建议只保留三类动效：

- 首屏渐入与轻微上移
- 媒体 hover 放大与遮罩显现
- 区块滚动进入

避免：

- 过多弹跳
- 大范围霓虹动画
- 不承载信息的装饰性过渡

## 12. 文案系统

### 12.1 首页文案

首页文案应该更像产品，而不是说明文档。

应强调：

- 用户能做什么
- 如何开始
- 为什么效果更可控

避免：

- 过长背景介绍
- 模型升级叙事占据首页主空间
- “我们一直想做一个……”这类品牌自述开场

### 12.2 文档文案

文档文案应该更像操作手册。

应优先使用：

- What it does
- When to use it
- How to prompt it
- Limits and notes
- Example

## 13. 组件策略

### 13.1 应该强化的组件

- Hero media
- Prompt input
- Upload entry
- Case showcase
- Capability preview

### 13.2 应该弱化的组件

- 首页无实际内容价值的 tab
- 假数据图墙
- 过多边框按钮
- 没有明确收益的说明文字

### 13.3 不建议默认使用的形式

- 首页大面积卡片网格
- 首屏统计条
- 浮动 SaaS dashboard 拼贴
- 与真实内容无关的抽象插画

## 14. 页面改版优先级

### P0

- 统一品牌叙事为 Lytai Studio 主站
- 首页 Hero 重构为真实媒体主导
- 首页 Discover 占位图替换为真实案例结构
- 文档体系从“Seedance 2.0 用户手册”改为 Cookbook 体系

当前完成度：

- 前三项已完成
- 文档体系重命名仍在进行中

### P1

- 建立 Capabilities 页面
- 重写文档一级导航命名
- 统一首页与文档页的语言和标签系统

新增事项：

- 把 `Create` 的本地历史切换到真实生成 API 返回
- 把 `Account` 的结果历史改成服务端持久化记录

### P2

- 补充更完整的动效系统
- 优化账号页、历史记录和结果浏览体验
- 建立更完整的品牌视觉资产体系

## 15. 验收标准

改版完成后，应满足以下判断标准：

- 用户进入首页 5 秒内能说出产品名是 Lytai Studio
- 用户进入首页 5 秒内能理解这是一个 AI 创作产品
- 用户进入首页 10 秒内能找到开始创作入口
- 用户浏览文档时不会误以为自己离开了主产品站
- Seedance 2.0 被理解为能力模块，而非站点主品牌

## 16. 后续实现建议

建议按以下顺序推进：

1. 重构首页信息架构
2. 替换首页首屏媒体与案例区
3. 重命名 Cookbook 体系与导航结构
4. 重写部分首页与文档文案
5. 最后再做动画与视觉细修

## 17. 最终定义

Lytai Studio 是产品。

Seedance 2.0 是引擎能力。

首页负责吸引、解释和转化。

Create 负责操作和生成。

Cookbook 负责教学和辅助转化。
